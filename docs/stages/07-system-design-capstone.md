# 第 7 阶段：系统设计、故障演练与最终答辩

## 1. 本阶段目标

M7 不再增加更多框架，而是把前六个阶段的产物组织成一套能解释、能估算、能排障、能迁移的系统方案。完成后你需要能够：

1. 从一次用户请求讲清 UI、API、Agent、工具、RAG、记忆、观测和部署边界。
2. 用业务变量估算并发、Token 吞吐、SSE 连接、日志体积和模型成本，而不是猜服务器数量。
3. 区分重试、幂等、补偿、降级和恢复，避免重复执行副作用。
4. 从 `run_id` 和事件序列定位模型、工具、检索、传输或权限故障。
5. 把研究助手迁移成另一个业务 Agent，并说明复用、替换和新增的部分。
6. 在 12～15 分钟内演示正常路径、失败路径、安全拒绝和工程边界。

建议分四次完成，每次 90～120 分钟：架构盘点、容量与可靠性、迁移设计、演示答辩。

## 2. 当前边界

- 当前仓库是单机、默认离线、进程内状态的教学实现，不是多租户生产平台。
- `capstone-architecture.md` 同时画出现状和生产目标；虚线目标组件不能描述成已完成。
- 容量示例是计算方法，不是压测结果；模型价格必须在实际答辩当天重新查询并标注来源日期。
- 协作式取消、静态 Token、内存审批和内存状态的限制必须主动说明。
- Docker Compose 配置已验证；只有 Docker Engine 实际可用并完成镜像启动后，才能勾选容器运行验收。

## 5. 跟练一：画出现状架构

### 目标

从真实代码反推架构，避免先画理想平台再强行对应实现。

### 执行动作

1. 从 `frontend/src/composables/useAgentDesk.ts` 沿请求进入 `backend/app/main.py`。
2. 继续追到 `InMemoryRunService`、`ManualAgentLoop`、`ToolRegistry` 和 `RunObserver`。
3. 对 RAG、记忆、审批、匿名 capability 分别写出 owner、生命周期、持久化位置和读取权限。
4. 在架构图上用实线标当前调用，用虚线标生产适配。

### 必做练习

选择一次数字工具运行，在纸上写出：

```text
请求字段 -> 身份/会话校验 -> run_id -> 模型决策
-> 工具授权/Schema -> handler -> 领域事件 -> SSE/观测
```

每个箭头旁标出失败码或终态。若无法指出某个数据的 owner，回到代码确认，不要用“平台会处理”代替。

### 通关标准

- 能解释 session ID、匿名 capability、principal、run ID 和 tool call ID 的差异。
- 能指出 UI、SSE 和日志为什么都不是真实任务状态的唯一来源。
- 能说明目标系统中的数据库、队列和 Trace 平台为何尚未加入当前代码。

## 6. 跟练二：容量、成本与 SLO

### 目标

把模糊的“用户会很多”改成可验证假设。

### 估算模板

填写下面的数据并保留来源：

| 变量 | 你的值 | 来源/日期 | 风险区间 |
| --- | --- | --- | --- |
| 日活用户与每人运行数 |  | 产品假设 |  |
| 平均/峰值 RPS |  | 日志或业务预测 |  |
| p50/p95 运行秒数 |  | 压测或供应商基线 |  |
| 平均输入/输出 Token |  | 真实 usage 样本 |  |
| 每运行事件数与平均字节 |  | 观测样本 |  |
| 模型单价 |  | 官方价格与查询日期 |  |
| 目标可用性与恢复时间 |  | 业务等级 |  |

使用以下公式：

```text
并发 ≈ 峰值 RPS × p95 秒数
日 Token = 日运行量 × 平均 Token/运行
事件存储/日 = 日运行量 × 事件数/运行 × 平均事件字节
月模型成本 = 月输入 Token × 输入单价 + 月输出 Token × 输出单价
```

至少计算保守、预期和峰值三个场景，再决定限流、并发、预算告警与保留期。

### 易错点

- `usage=null` 不能作为 0 纳入平均。
- 模型耗时和工具耗时不能只看总时长。
- SSE 连接数与 HTTP 请求数不是同一个指标。
- 日志正文、Trace 和指标的成本模型不同，不能无限保留全部原始事件。

### 通关标准

能在五分钟内重算一个变量变化 2 倍后的并发与成本，并说明哪个假设最不可靠、如何采样验证。

## 7. 跟练三：故障、重试与恢复

### 故障演练矩阵

| 场景 | 注入方法 | 预期行为 | 恢复证据 |
| --- | --- | --- | --- |
| 模型瞬态失败 | 使用 `RetryableModelError` fixture | 有限重试，受最大次数约束 | `model.retrying` 与终态 |
| 普通程序错误 | runner 抛普通异常 | 不盲目重试，形成失败观测 | 稳定错误分类 |
| 高风险工具无审批 | 调 `publish_report` | handler 不执行 | `approval_required` |
| 审批重放 | 重复同一精确调用 | 第二次拒绝 | `approval_already_consumed` |
| SSE 中断 | 前端 AbortController | 发出协作式取消，等待有上界 | UI 状态与后台回收 |
| RAG 无证据 | 查询无共享 token 内容 | 明确拒答 | evidence 为空、review 拒绝 |
| 代码路径逃逸 | M6 `../` fixture | I/O 前拒绝 | 外部文件不变 |

### 排查记录模板

```text
用户现象：
run_id / 请求 ID：
领域终态：
最后成功事件：
错误层：模型 / 工具 / 检索 / 权限 / 传输 / 基础设施
是否有副作用：
是否允许重试，依据：
最小复现：
修复后的定向测试：
完整回归：
仍有风险：
```

### 通关标准

每个故障都能说明“为何能重试或为何不能”，且不会把日志/观测失败变成成功业务请求的失败原因。

## 8. 跟练四：迁移到新业务场景

### 推荐场景：内部事故分诊助手

输入告警摘要和内部运行手册，输出证据化诊断建议；查询监控是只读工具，执行回滚是高风险工具。

| 主线能力 | 直接复用 | 需要替换 | 需要新增 |
| --- | --- | --- | --- |
| Agent Loop/事件 | 停止、工具、终态协议 | 领域 Prompt/评测 | 事故严重级别 |
| RAG | KnowledgeBase 与引用 | 课程文档换运行手册 | 文档 ACL、版本时间 |
| 工具安全 | RBAC、Schema、精确审批 | `publish_report` 换监控查询/回滚 | 双人审批、变更窗口 |
| 记忆 | 显式批准/删除 | 偏好字段 | 事故数据保留期 |
| UI/SSE | 时间线、取消、错误 | 业务文案 | 人工接管入口 |
| 评测 | 固定样例与错误分类 | 任务断言 | 漏报/误报与危险动作指标 |

### 威胁建模

至少分析：恶意运行手册指令、越权查看服务、错误回滚、重复回滚、过期文档、敏感日志泄露、模型不可用和监控接口超时。

### 通关标准

产出一页迁移方案，包含数据、工具、权限、审批、评测、降级和未解决风险；不能只写“更换 Prompt”。

## 9. 跟练五：一键验收与答辩

### 自动验证

在项目根目录运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\verify.ps1
```

如果只想在没有 Docker CLI 的环境检查代码：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\verify.ps1 -SkipCompose
```

脚本不会安装依赖、启动公网请求或写入密钥。它会依次执行完整后端回归、代码 Agent 离线 Demo、`pip check`、Vue/MCP 构建和可选 Compose 配置检查，任一步失败即停止。

### 演示

按 `docs/capstone-demo-script.md` 演示。至少包含一个正常工具路径、一个有引用 RAG、一个匿名会话隔离、一个高风险审批拒绝/重放、一个 M6 安全拒绝和一次默认离线评测。

### 通关标准

- 全部验证通过，或明确记录唯一未通过项、原因和外部前置条件。
- 演示在 15 分钟内完成，正常与失败路径都有证据。
- 能回答“为何不用更复杂架构”和“何时必须升级”的双向问题。

## 10. 一页速查

```text
先定边界：谁拥有数据，谁能写，多久删除
再算容量：RPS × p95 = 并发；运行量 × Token/事件 = 成本
副作用：审批 + 幂等 + 终态查询，传输失败不等于没执行
重试：只重试显式瞬态；总次数、退避和截止时间都有限
降级：无证据则拒答；高风险依赖不可用则人工接管
恢复：状态真相在持久层，不在 SSE 连接或页面状态
观测：run_id + 分项耗时 + usage + 事件 + 错误类别
答辩：当前实线、目标虚线、假设有来源、限制主动说
```

## 11. 自测与场景题

1. SSE 已断开但退款工具可能成功，下一步为什么不是重发整个请求？
2. 如果 p95 从 5 秒升到 20 秒而 RPS 不变，并发如何变化？
3. 模型、工具、RAG 各自应该设置什么超时，为什么总截止时间仍需要？
4. 审批记录和任务入队之间崩溃，如何用事务或 Outbox 避免不一致？
5. 单实例内存状态迁移 PostgreSQL 时，哪些接口和事件不应变化？
6. 为什么把 Agent 拆成更多微服务可能降低而不是提高可靠性？
7. 真实模型评测为什么不能替代确定性 Mock 回归？
8. 什么时候应该用队列，什么时候同步 HTTP 更简单可靠？

## 12. 费曼复述

请用“机场运行系统”类比解释：

1. API、Agent Loop、工具和数据库分别像哪个岗位。
2. run ID、审批和幂等键分别解决哪种混乱。
3. SSE 为什么像航班显示屏，不是飞机真实位置的唯一来源。
4. 降级、重试和人工接管为什么不能互相替代。
5. 容量估算为什么必须从航班量与周转时间开始。

复述必须包含一次“显示屏断线但飞机可能已起飞”的副作用案例，以及一个明确的系统边界。
