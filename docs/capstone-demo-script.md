# 最终演示脚本（12～15 分钟）

## 演示前检查

1. 使用项目 `.venv`，不要在终端历史中粘贴真实密钥。
2. 运行完整后端测试、Vue 构建、MCP 构建和 Compose 配置检查。
3. 启动后端与前端，确认 `/health` 与 `/ui-health`。
4. 准备两个匿名 session、一个 observer 身份和一条精确审批；只使用教学 Token。
5. Docker Engine 未启动时明确说明只完成配置验证，不伪造容器运行结果。

## 必演失败路径

至少演示三项，且每项先预测结果再执行：

1. 用第二个匿名 capability 调用第一个 session，返回 404。
2. 无审批调用 `publish_report`，工具 handler 不执行。
3. 同一审批第二次重放，被拒绝。
4. RAG 无证据时明确拒答。
5. 代码 Agent 尝试 `../` 路径或非白名单命令，被策略层拒绝。
6. 浏览器 Agent 导航到相似恶意域名，被 exact-origin 校验拒绝。

## 预置故障排查话术

```text
先确认用户可见现象
-> 用 run_id 找到终态与事件序列
-> 判断模型、工具、检索、传输还是权限层
-> 检查是否允许重试，副作用是否已有幂等结果
-> 做最小修复并运行对应测试 + 完整回归
```

不要先改 Prompt，也不要只以 HTTP 200 判断 Agent 正常。

## 答辩常见追问

### 为什么先手写 Agent Loop？

因为需要先看清“模型决策—程序校验—工具执行—结果回传—停止条件”的最小闭环。框架改变表达方式，不取消这些责任。

### 为什么不用前端角色控制权限？

前端状态可被修改，只能改善交互；最终授权必须使用服务端验证的主体、角色和审批状态。

### 为什么 SSE 断线不能直接重发？

传输失败不代表副作用没执行。应先按 run ID 或幂等键查询终态，再决定恢复、补偿或人工处理。

### 为什么 `usage=null` 比 `0` 更好？

`null` 表示供应商没有提供可信数据；零会污染预算和容量结论。

### 什么时候引入队列？

当任务明显长于 HTTP 生命周期、需要独立扩缩容、持久重试或故障恢复时。当前快速 Mock 路径没有必要为了架构图提前引入。

## 演示结束标准

- 正常路径与失败路径都可复现。
- 能指出每个安全判断所在的程序层。
- 不展示或打印真实密钥、Prompt 正文和敏感工具参数。
- 对未实现能力明确说“规划”或“限制”，不描述为已完成。
- 能把研究助手迁移到客服、内部运维或文档审核场景，并说明需要替换的数据、工具与审批策略。
