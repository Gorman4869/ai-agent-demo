# 项目编码规约 v1.0

## 1. 项目指纹

- 项目名称：AI Agent Learning UI
- 项目路径：`ai-agent-demo/frontend`
- 技术栈摘要：Vue 3、Composition API、TypeScript、Vite、原生 CSS、原生 Fetch
- 构建工具：Vite 8，类型构建使用 `vue-tsc`
- 语言形态：Vue SFC + strict TypeScript
- UI 组件库：无
- 状态管理：组合式函数内的 Vue 响应式状态
- 路由与国际化：当前均未引入
- 样式方案：全局 CSS 变量与少量组件 `scoped` CSS
- 请求封装：`src/services/agentApi.ts`

## 2. 技术栈

- 框架与版本：Vue `^3.5.0`，TypeScript `5.9.3`，Node 已验证 `22.16.0`。
- 关键依赖：只使用 Vue；不引入 UI、状态、路由或请求库。
- 开发命令：`npm run dev`。
- 构建命令：`npm run build`，必须同时通过 `vue-tsc -b` 与 `vite build`。
- 浏览器消费稳定业务事件，不解析模型供应商的原始流。

## 3. 目录规范

- `src/components`：无业务请求的可复用展示组件。
- `src/composables`：页面用例状态和动作编排。
- `src/services`：HTTP、SSE、错误协议与请求 URL。
- `src/types`：跨组件及前后端契约类型。
- `src/styles`：全局变量、重置、响应式页面样式。
- `App.vue`：组合页面，不实现 SSE 分帧或错误解析。
- 项目规模尚小，不提前增加 router、store 或 api 子模块层级。

## 4. 命名规范

- Vue 组件使用 `PascalCase.vue`，普通 TypeScript 文件使用 `camelCase.ts`。
- 变量与函数使用 `camelCase`；类型和错误类使用 `PascalCase`。
- 事件处理函数使用 `handle` 前缀，布尔状态使用 `is`、`has`、`can` 前缀。
- API 字段保持后端契约的 `snake_case`，进入视图状态后使用本地既有命名。

## 5. 组件规范

- 统一使用 `<script setup lang="ts">` 与 Composition API。
- Props 使用类型形式 `defineProps<T>()`；组件只接收展示所需的最小数据。
- 页面状态和异步动作集中在 `useAgentDesk()`，组件不复制请求逻辑。
- 加载、错误、空状态、停止动作和 `aria-live` 必须保留。

## 6. TypeScript 规范

- `strict`、`isolatedModules` 和 `noEmit` 保持开启。
- 禁止隐式/显式 `any` 与无依据的非空断言。
- 未知异常使用 `unknown`，经 `ApiError` 或 `Error` 收窄。
- 纯类型导入使用 `import type`；第三方导入与本地导入之间空一行。
- API 返回值先声明契约类型，再进入组合式状态。

## 7. CSS 规范

- 只使用原生 CSS；颜色、字体、间距和状态色优先复用 `:root` 变量。
- 页面布局在 `src/styles/main.css`，组件内部结构可使用 `scoped`。
- 保留键盘焦点、`prefers-reduced-motion` 与 720/1050px 响应式断点。
- 不混入 Tailwind、CSS-in-JS、Less、Sass 或外部字体依赖。

## 8. 接口请求规范

- 所有 URL 和 Fetch 逻辑集中在 `src/services/agentApi.ts`。
- `/api` 使用相对地址，由 Vite/Nginx 代理 FastAPI。
- JSON 请求统一经过 `requestJson()`；非 2xx 统一转为 `ApiError`。
- SSE 由 `streamRun()` 解析，组件只消费 `AgentEvent`。
- 浏览器不保存服务端密钥或静态 Bearer Token。匿名会话创建响应中的 capability token 只保存在 `useAgentDesk()` 内存状态，并由 `streamRun()` 通过 `X-Session-Token` 回传，不写入日志或持久化存储。
- 固定教学资料在服务启动时装载；无参数的 `/api/knowledge/demo-seed` 只返回就绪信息。任意知识写入仍由后端角色保护，保留 ID `agent-course` 不能通过通用写接口覆盖。

## 9. 工具函数使用规则

- 协议解析、错误转换和请求头处理优先复用 service 内现有函数。
- 与单个组合式用例绑定的小函数留在对应 composable。
- 只有被两个以上模块复用且职责稳定时才新增公共工具文件。

## 10. 路由、权限与状态管理

- 当前没有路由与全局 Store，不为单页面提前引入。
- 浏览器只展示后端授权结果，不能通过前端布尔值实现安全边界。
- 真实登录接入后应使用服务端会话或受验证令牌；不得把演示服务端 Token 打包进 Vite 产物。
- 页面级状态由 `useAgentDesk()` 管理，跨页面需求出现后再评估 Pinia。

## 11. 注释、文案与国际化

- 代码以清晰命名为主，只为协议边界或非直观取舍写注释。
- 当前界面直接使用中文文案；引入第二语言后再统一迁移 i18n。
- 错误文案必须告诉用户发生了什么，不能直接显示堆栈或内部异常。

## 12. 禁止写法清单

- 禁止在组件里散落 URL、Fetch、SSE 分帧或响应错误解析。
- 禁止解析供应商原始流、把 API Key/静态服务端 Token放入前端环境变量。
- 禁止新增 UI、状态、路由、请求或样式依赖，除非功能确有需要并经用户确认。
- 禁止用前端角色、隐藏按钮或请求参数替代后端授权。
- 禁止无关重构、批量格式化和改变现有视觉语言。

## 14. 维护规则

- 新增路由、Store、UI 库、鉴权方式或请求抽象时刷新本规约。
- 仅增加同类组件或接口时，沿用现有规则，不重复生成文档。
- 切换到其他仓库时重新分析，不能复用本项目约定。
