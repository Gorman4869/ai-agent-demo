# AI Agent 系统学习与跟练 Demo 设计规格

## 1. 项目目标

在 `ai-agent-demo` 中建设一套面向前端开发者的 AI Agent 学习项目。课程以一个持续演进的“AI 研究与知识库助手”为主线，将学习大纲中的 30 个主题转化为可运行实验、阶段任务、工程实践和可验证的学习成果。

成功标准不是阅读完资料，而是学习者最终能够独立完成、解释、排查和扩展一个包含 Agent 循环、工具调用、MCP、RAG、记忆、多 Agent、流式 UI、权限、测试、可观测性和部署能力的完整应用。

## 2. 目标学习者与默认约束

- 学习者已有 Vue 前端开发经验，但不假设已有 Python 或 AI 工程经验。
- 默认周期为 12 周，每周投入 8–10 小时；所有任务同时提供按里程碑推进的方式，便于调整进度。
- 主后端使用 Python，前端使用 Vue 3 与 TypeScript，Node.js 用于基础实验和 TypeScript MCP Server。
- 第一阶段不依赖真实模型或付费服务，提供 Mock 模型运行路径；真实模型通过环境变量启用。
- 不在仓库中保存 API Key、Token、密码或个人数据。
- 不要求一次安装所有依赖；各阶段只安装当前实验所需依赖，并在文档中列明用途。

## 3. 方案选择

采用“渐进式单项目 + 独立概念实验”的混合结构：

- 主线项目让前一阶段产物被后一阶段复用，形成真实工程经验。
- `labs` 中的最小实验用于隔离难点，避免学习者必须先理解完整项目才能观察一个概念。
- 每个阶段必须有可运行、可观察、可测试的产物，不以功能清单代替跟练步骤。

不采用 30 个完全独立 Demo，因为会产生大量重复代码并割裂工程能力；不采用一次性大型平台，因为学习曲线过陡且难以定位错误。

## 4. 技术架构

```text
Vue 3 + TypeScript Agent UI
        │ REST + SSE
        ▼
Python + FastAPI API 层
        │
        ├── 手写 Agent Loop / OpenAI Agents SDK / LangGraph
        ├── Tools / Skills / MCP Client
        ├── RAG / Memory / Workflow / Multi-Agent
        ├── Guardrails / Authorization / Evaluation
        └── Logging / Tracing / Cost Metrics
        │
        ├── PostgreSQL + pgvector（工程阶段）
        ├── Redis（队列、缓存或流式状态阶段）
        └── TypeScript MCP Servers
```

演进原则：先用标准库和内存实现讲清机制，再引入框架和基础设施。框架用于减少工程样板，不用于掩盖 Agent 循环、状态迁移和工具执行原理。

## 6. 五级学习路线

### L1：Agent 入门认知

覆盖 Agent、Node.js、Python、前端、LLM 推理和 Prompt 基础。学习者手写一个不依赖框架的最小 Agent Loop，并能说明模型、指令、上下文、工具和停止条件的职责边界。

通关证据：Mock 模式能够完成一次“判断是否调用工具—执行工具—生成结果”的循环，并通过基础单元测试。

### L2：工具与单 Agent 能力

覆盖 Function Calling、MCP、Agent Skill、Agent 架构、LangChain、LangGraph、上下文工程和 Harness。主项目形成可替换模型适配器、工具注册表、结构化输入输出和基础状态图。

通关证据：同一个业务工具既能被手写循环调用，也能通过 MCP 暴露；错误参数能够被校验并返回可诊断错误。

### L3：工作流与知识能力

覆盖多 Agent、Workflow、RAG、记忆、任务推理、Agent UI、后端 API、向量数据库和流式输出。主项目能够检索本地知识、执行分步任务，并在 Vue UI 中显示事件流和引用。

通关证据：针对固定知识集回答问题时能够返回来源；刷新页面后会话可恢复；SSE 中断后前端能给出明确状态。

### L4：工程质量与生产准备

覆盖可观测性、自动化测试、工程化部署、安全治理与权限控制。加入结构化日志、trace、Token/耗时统计、评测集、权限边界、敏感信息处理和 Docker 部署。

通关证据：固定评测集可重复运行；越权工具调用会被拒绝并记录；项目可以依据文档在干净环境启动。

### L5：高级 Agent 与迁移

覆盖多模态 Agent、代码 Agent、浏览器 Agent和系统设计场景题。高级主题作为共享基础设施上的扩展模块，不破坏主线项目核心边界。

通关证据：独立选择一个高级 Agent 场景完成扩展，说明安全边界、成本、失败恢复方案及未采用其他方案的原因。

## 8. 主线项目组件

### 8.1 模型适配层

提供统一聊天、结构化输出、流式事件和工具调用接口。Mock 实现用于零成本测试，真实提供商实现从环境读取配置。上层不能直接依赖某家模型的响应对象。

### 8.2 Agent 运行时

依次实现手写循环、SDK 运行器和 LangGraph 工作流。三种实现共享领域接口和测试样例，以便比较抽象层级、可控性和适用边界。

### 8.3 工具与 MCP

工具定义包含名称、描述、输入 Schema、权限要求、超时、执行函数和错误映射。MCP Server 只暴露经过许可的能力；文件类工具必须限制工作目录，写操作需要显式审批。

### 8.4 RAG 与记忆

RAG 流程拆分为加载、切分、嵌入、存储、检索、重排、上下文构造和引用输出。早期使用确定性 Mock Embedding 与内存索引，工程阶段迁移到 PostgreSQL/pgvector。短期会话状态与长期用户记忆分开存储和评测。

### 8.5 Vue Agent UI

界面展示消息、任务状态、工具调用、流式内容、引用来源、错误恢复和成本摘要。前端只消费稳定事件协议，不解析模型厂商的原始流格式。

### 8.6 评测与可观测性

每次运行生成关联 ID，记录节点、工具、耗时、Token、错误和最终状态。评测覆盖答案依据、工具选择、权限拒绝、异常恢复和回归，不只比较文本是否完全一致。

## 9. 数据流与事件协议

1. 前端创建或恢复会话并提交消息。
2. API 校验身份、会话权限、输入长度和请求参数。
3. Agent 运行时加载短期状态，根据任务选择直接回答、检索或工具调用。
4. 每个状态变化产生统一事件，如 `run.started`、`message.delta`、`tool.started`、`tool.completed`、`citation.added`、`run.failed`、`run.completed`。
5. 后端通过 SSE 向前端推送事件；前端按运行 ID 更新视图。
6. 运行结束后保存消息、引用、工具审计、指标和必要记忆。

SSE 断线不自动重复执行有副作用的工具。客户端恢复时先查询运行状态，再决定重连事件流或展示最终结果。

## 10. 错误与安全设计

- 模型、工具、检索、存储和传输错误使用不同错误码与日志字段。
- 面向用户的错误不包含堆栈、密钥、内部 Prompt 或敏感工具参数。
- 工具输入必须经过 Schema 校验；外部调用设置超时、有限重试和取消机制。
- 有副作用或高风险的工具默认要求人工批准，不允许模型自行提升权限。
- Prompt Injection 防御同时覆盖系统指令隔离、检索内容标记、工具权限和输出检查，不能只依靠一段 Prompt。
- 代码和浏览器 Agent 只在受限实验环境运行，不默认拥有宿主机任意命令、文件或账号权限。

## 11. 测试策略

- 单元测试：状态转换、工具 Schema、权限判断、切分与检索、事件序列。
- 契约测试：前后端事件协议、MCP 工具契约、模型适配器输出。
- 集成测试：Mock 模型驱动完整 Agent Loop，覆盖成功、超时、错误参数和中断。
- 评测测试：固定问题集验证引用、工具选择、拒答、任务完成率和成本阈值。
- UI 测试：流式更新、工具状态、断线、错误提示和会话恢复。
- 部署验证：构建、健康检查、配置缺失提示和容器启动。

真实模型测试单独标记，避免默认测试产生费用或受网络波动影响。

## 12. 学习文档标准

每个阶段文档必须包含：目标、前置知识、预计时间、核心原理、真实工作映射、逐步操作、涉及文件、关键代码解释、必做练习、完成证据、常见错误、排查顺序、复盘问题和可复用沉淀。

完整计划额外包含：20% 关键知识分类、12 周安排、阶段验收、概念/实操/场景自测题、一页速查表、精选官方资源，以及要求学习者用简单语言解释概念和边界的费曼复述任务。

## 13. 最终交付与验收

最终交付包括可运行代码、学习文档、测试、评测数据、部署说明、架构说明和演示脚本。学习者需要现场完成以下任务：

1. 从零启动 Mock 模式并演示一次完整运行。
2. 解释 Agent Loop、Workflow 与普通聊天接口的区别。
3. 新增一个带 Schema 和权限的工具，并接入 UI 事件流。
4. 对一份新资料建立索引，返回可核对引用。
5. 定位一个预置的流式、检索或工具调用故障。
6. 展示越权调用被拒绝及对应审计记录。
7. 运行自动化测试与评测并解释失败项。
8. 将系统迁移到一个未练过的相似业务场景，说明需要复用和替换的模块。

满足上述证据，且没有在代码中写入密钥，才视为完成课程。

## 14. 非目标

- 不训练或微调基础大模型。
- 不建设通用低代码 Agent 平台。
- 不在第一版接入多个真实模型供应商。
- 不追求生产级 Kubernetes、多租户计费或大规模分布式调度。
- 不让高级代码或浏览器 Agent 在未经隔离和批准时执行真实高风险操作。
