# AI Agent 课程高效交付协议

## 协议元数据

- 协议版本：1.0
- 确认日期：2026-07-16
- 协议状态：`accepted`
- 适用范围：`ai-agent-demo` 的 C0 与 M8–M14 后续课程生成、代码实现、验证和交接
- 默认模式：课程优先、里程碑验收
- 变更规则：只有用户明确确认后才能修改本协议；当前任务和状态仍只写入 [`status.md`](status.md)

本协议约束的是课程生产方式，不缩短学习者在 [`learning-plan.md`](../learning-plan.md) 中的训练时间，也不降低任务明确写出的验收条件。目标是在保留真实、可运行、可验证学习闭环的前提下，停止重复文档、无风险收益的测试堆叠和过早生产化。

## 1. 课程最终目标

课程不是以文件数量、代码行数或测试数量为完成标准。学习者完成后应能独立完成以下工作：

1. 解释并手写 Agent Loop，理解模型、工具、状态和控制流的边界。
2. 使用真实框架进入实际调用链，而不是只安装或导入依赖。
3. 构建 MCP、工作流、上下文、记忆、RAG、流式 UI 和后端 API 的完整链路。
4. 处理失败、取消、恢复、权限、成本、日志、测试和部署问题。
5. 把课程方案迁移到真实业务，并能解释技术取舍。

每个里程碑最终形成以下闭环：

```text
原理 -> 最小实验 -> 主线实现 -> 自动化验证 -> 故障排查
     -> 工作场景题 -> 费曼复述 -> 可展示产物
```

原子任务负责产生可复用的真实纵切；所属里程碑的跟练与验收任务负责把这些纵切汇总为完整教学材料。不得要求每个原子任务重复编写整章教程。

## 2. 不可降低的质量底线

无论任务时间盒多短，以下内容都不能省略：

1. **真实调用链**：声称使用某框架时，必须执行该框架的公开 API 或运行时路径。依赖存在、成功 import、构造对象或手写等价逻辑都不能冒充框架实现。
2. **最小可运行产物**：默认离线、确定性、无密钥可运行；命令、输入和预期结果必须清楚。
3. **关键行为验证**：至少覆盖正常路径、代表性失败路径，以及本任务实际涉及的安全或权限边界。
4. **证据诚实**：明确区分已运行、未运行、跳过、失败、离线模拟和真实在线结果；不能把 Fake、Mock 或配置检查描述成在线兼容证据。
5. **范围边界**：说明本任务解决什么、刻意不解决什么，以及后续由哪个稳定任务接管。
6. **学习迁移**：在原子任务交接或里程碑教程中说明真实工作场景、常见错误和排查入口。
7. **连续性**：状态、验证、known issue 和下一动作必须足以让新模型不依赖聊天记录继续工作。

如果时间盒与质量底线冲突，应缩小本次纵切或把非必要加固移回已规划的后续任务，不能伪造完成状态。

## 3. 原子任务与里程碑的职责

| 层级 | 必须交付 | 不要求重复交付 |
| --- | --- | --- |
| 原子任务 `T1...Tn` | 最小真实纵切、关键测试、定向验证、简短交接、明确边界 | 整章教程、完整题库、一页速查表、全课程审计 |
| 跟练与验收任务 | 串联本里程碑所有产物、完整跟练、概念/实操/场景题、排错、速查表、费曼复述 | 重写已经稳定的实现细节 |
| 最终验收 | 30 项映射、作品演示、综合故障演练、迁移说明和证据索引 | 为增加数量而重复测试或复制文档 |

任务的明确验收契约、已接受 ADR 和用户最新指令高于本协议的一般建议，但不能绕过授权门和证据真实性。

## 4. 任务等级与时间盒

开始修改前必须选择一个等级，并在本轮计划或 handoff 中记录。

| 等级 | 适用范围 | 默认生产时间盒 | 验证与复审 |
| --- | --- | ---: | --- |
| B：普通课程任务 | 离线实验、普通适配器、确定性功能、教程整合、框架对照 | 30–90 分钟 | 有代码或行为变化时约 6–12 个关键新增用例或等价覆盖；纯文档任务检查内容、链接、连续性和 diff；一次自审或一次聚焦复审 |
| A：关键工程任务 | 并发、持久化、身份权限、副作用、安全、跨模块公共契约、迁移、部署 | 2–4 小时 | 风险驱动测试；一次独立聚焦复审，只有仍有阻断风险时才追加复审 |
| C：外部门禁任务 | 在线模型、付费 API、真实数据库/容器、浏览器、远程系统 | 离线准备按 B/A；外部执行等待授权 | 缺少授权或环境时记录未验证范围，不伪造、不反复尝试 |

测试数量是控制代码或行为变化规模的参考，不是新的 KPI。一个高价值参数化测试可以覆盖多个行为；一个安全关键任务也可以按实际风险超过参考数量。纯文档任务不为凑数量新增业务测试。

### 时间盒检查点

- B 类任务进行到约 60 分钟仍没有形成可运行纵切时，立即停止扩张，检查是否混入了后续生产化内容。
- B 类达到 90 分钟仍未完成时，拆成不改变稳定任务 ID 的内部原子步骤，并先交付其中可验证的一步。
- A 类进行到约 2 小时时重新核对风险清单；达到 4 小时时保留最小安全结果并交接，不静默扩张范围。
- C 类缺少授权、密钥、Docker Engine 或外部服务时，只完成安全的离线准备和 fail-closed 门，不让等待时间阻塞其他离线任务。

上述时间盒约束的是模型生成课程与工程产物的时间，不代表学习者应跳过理解、跟练、排错和复述。

## 5. 证据等级

| 等级 | 含义 | 可以证明 | 不能证明 |
| --- | --- | --- | --- |
| E0 | 依赖或文件存在 | 环境中可能具备该能力 | 框架已被使用 |
| E1 | import、配置或对象构造成功 | 基础 API 形状兼容 | 实际执行链可用 |
| E2 | 真实框架公开 API 在离线 Fake/Mock 边界下执行 | 框架真正进入调用链，映射逻辑可回归 | Provider 或外部系统真实兼容 |
| E3 | 与共享领域契约、错误语义和相关回归集成 | 可替换实现具备一致的课程级行为 | 真实网络、费用或生产容量 |
| E4 | 经单次授权运行真实外部服务并记录结果 | 本次指定环境和版本的在线证据 | 永久兼容或无限预算 |

任务计划决定需要达到哪个等级。若任务明确要求 E4，只有 E2/E3 时最高只能记录为 `code_complete`；不得用 Mock、截图、配置展开或历史结果补成 E4。

## 6. 标准执行流程

每个新模型或新会话按以下顺序工作：

1. **恢复现场**：运行 `git status --short`、查看最近提交，按 [`README.md`](README.md) 的恢复流程读取状态、协议、计划、ADR、handoff 和验证证据。
2. **确认单一任务**：只处理 [`status.md`](status.md) 的当前任务；写清本次内部原子步骤，不顺手进入下一个任务。
3. **选择等级**：根据风险选择 A、B 或 C，列出本次质量底线、明确非目标和时间盒。
4. **实现最小纵切**：优先让一条真实调用链从输入走到安全结果，再补代表性失败和安全边界。
5. **运行定向验证**：先跑最靠近修改的测试和必要回归；没有触发全量门时不运行全仓重复验证。
6. **聚焦自审**：检查错误分类、敏感信息、取消/副作用、兼容性和未验证声明；不为普通任务安排多轮泛化审查。
7. **记录证据**：按实际结果追加 verification，更新必要的 known issue、status 和简短 handoff。
8. **提交与恢复检查**：检查 diff 和工作区，仅提交本任务文件；提交后用最小回归确认可恢复。

出现失败时先解释原因并修复当前纵切。只有失败揭示了稳定缺口时才登记 known issue，不把每个临时拼写错误写成长期风险。

## 7. 测试与全量验证策略

### 每个含代码或行为变化的原子任务都要做

- 修改模块的定向测试。
- 一条正常路径和一条代表性失败路径。
- 本任务确实涉及的身份、数据边界、敏感信息或副作用检查。
- 与被修改公共契约直接相关的既有回归。

纯文档任务按实际范围执行内容一致性、自包含链接、连续性和 diff 检查，不要求虚构正常/失败业务用例，也不为满足测试数量改动业务代码。

### 仅在以下情况运行全量验证

- 当前任务是里程碑跟练、验收或发布门。
- 修改了依赖、锁文件、构建配置或跨前后端公共接口。
- 修改了被多个里程碑共享的核心领域契约，并且定向回归不足以证明兼容性。
- 修复了只在全量测试中出现的回归。
- 任务计划或用户明确要求。

普通文档任务不重复运行 200 多项后端、前端构建、MCP 构建和 Compose 全套验证；连续性检查、Markdown 链接检查和 diff 检查足够时，应如实记录验证范围。

## 8. 文档、ADR、复审与提交节奏

### 文档

- 动态状态只写 [`status.md`](status.md)。
- 实际命令和结果只追加到 [`verification-log.md`](verification-log.md)。
- handoff 只记录本轮不可变快照、修改文件、失败尝试、未验证范围和下一动作。
- 普通原子任务只补当前章节的必要说明；所属里程碑验收时再统一润色完整教程。
- 不在 README、阶段教程和大纲映射中复制当前任务状态。

### ADR 与复审

- 只有难以逆转、跨任务或改变公共边界的决策才新增 ADR。
- B 类默认一次自审或一次聚焦只读复审。
- A 类默认一次独立、基于明确风险清单的复审；只有阻断问题仍存在时才增加第二次。
- 不因“看起来更稳”安排三份内容重复的审计。

### Git 提交

- B 类任务通常一个提交包含代码、测试和简短证据文档。
- A 类可以使用一个实现提交和一个验证/交接提交；不要再为回填刚生成的 hash 创建第三个“最终状态”提交。
- 文档不能预知尚未创建的 commit；新 HEAD 由下一份 verification 或 handoff 记录。
- 不重写用户提交，不执行 `git push`，远程地址和推送必须另行授权。

## 9. 过度工程化停止规则

以下现象出现时必须暂停并重新缩小范围：

- 普通实验开始设计生产级租约、分布式锁、完整成本账本或跨进程恢复，而后续 M10–M13 已有对应任务。
- 为同一正常/失败行为增加多组只改变表面输入的重复测试。
- 为可逆的局部实现新增 ADR。
- 每个子任务都重写完整阶段教程、速查表和题库。
- 为普通任务安排多名审查者检查相同问题。
- 为了让状态变成 `verified` 而模糊在线、Docker、数据库或 Provider 未验证范围。

处理方式：保留质量底线所需的最小实现，把生产强化明确指回已有稳定任务；如果计划没有承接点，再请求用户决定是否扩张范围。

## 10. 必须重新取得用户授权的动作

以下授权不能从历史会话、旧批准或本协议推断：

- 安装、升级或删除依赖。
- 执行在线模型、付费 API 或可能产生费用的外部调用。
- 读取或使用真实密钥、Token、个人数据。
- 配置远程 Git、执行 push、创建 PR 或向外部系统写入。
- 破坏性 Git、文件、数据库或部署操作。
- 引入新基础设施、UI/状态库，或把当前任务扩大为新的产品功能。

没有授权时继续完成安全的离线部分，并在状态和 handoff 中写出解除条件。

## 11. 原子任务完成清单

只有以下问题都有明确答案，本轮原子步骤才可以结束：

- [ ] 当前任务和内部原子步骤是否与 `status.md` 一致？
- [ ] 是否记录了 A/B/C 等级和时间盒？
- [ ] 框架是否真实进入调用链，而不只是依赖存在？
- [ ] 最小 Demo 或主链是否可以按文档命令运行？
- [ ] 有代码或行为变化时，是否覆盖正常、代表性失败和实际涉及的安全边界？纯文档任务是否完成内容、链接、连续性和 diff 检查？
- [ ] 是否如实标明 E0–E4 证据等级和未验证范围？
- [ ] 是否避免提前实现后续里程碑已有的生产强化？
- [ ] 是否只运行了与风险相称的验证，并记录真实结果？
- [ ] status、verification、known issue 和 handoff 是否各守唯一职责？
- [ ] 下一位执行者是否能在没有聊天记录时继续？

## 12. 可复制的新模型启动提示词

```text
你正在接手 ai-agent-demo 课程工程。不要依赖聊天记录推断进度。

开始前必须依次：
1. 运行 git status --short 和 git log -6 --oneline。
2. 阅读 AGENTS.md。
3. 阅读 docs/continuity/README.md。
4. 阅读 docs/continuity/status.md。
5. 阅读 docs/continuity/course-delivery-playbook.md。
6. 阅读 implementation-plan 中当前任务、相关 ADR、最新 handoff 和关联 verification。
7. 检查实际代码与记录是否一致，并重跑 handoff 指定的最小恢复测试。

只处理 status.md 的当前任务，不重做已有提交。采用“课程优先、里程碑验收”：
- 开始前把本轮标为 A/B/C 类并给出时间盒。
- 先交付最小但真实的可运行纵切；依赖存在或 import 成功不算框架完成。
- 有代码或行为变化的普通 B 类任务约 6–12 个关键新增用例或等价覆盖，只跑定向回归；纯文档任务只做内容、链接、连续性和 diff 检查。
- 全量验证只在里程碑、依赖/公共契约变化、发布门或计划明确要求时运行。
- 完整教程、题库、速查表和费曼材料在所属里程碑验收任务汇总，不在每个子任务重复扩写。
- 默认离线、无密钥、零费用；不得把 Fake/Mock 描述成在线证据。
- 未经用户新的明确授权，不安装依赖、不执行在线/付费调用、不读取密钥、不配置或推送远程 Git、不扩大任务范围。
- 结束时记录实际验证、未验证范围和下一条原子动作，保持 Git 可恢复。

如代码、验证日志和状态冲突，以可复现代码/测试证据为先；先登记漂移再继续实现。
```
